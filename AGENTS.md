# AliceBoost — правила работы

Общие договорённости владельца дополняются следующими правилами проекта.

- Работать в существующей копии `C:\Projects\AliceBoost` и постоянной ветке `feature/aliceboost`. `main` не менять без отдельной команды.
- Разрешены локальные изменения, проверки и коммиты. Push, публикация и деплой требуют отдельного разрешения.
- Сначала читать [спецификацию](docs/PROJECT_SPEC.md) и [дорожную карту](ROADMAP.md). Завершённые планы являются историей, а не действующими требованиями.
- Node.js 22+, встроенные API; новые зависимости и сервисы — только при согласованной необходимости.
- Автоматические проверки используют искусственные ключи и заменяют только внешний HTTP. Не обращаться к платным API автоматически и не загружать `.env` в тестах.
- Проверять фактический размер всего `session_state` в UTF-8, включая метаданные. Ответ Алисе должен иметь ограничение времени и понятный запасной сценарий.
- Не подменять неудачный поиск ответом модели без проверенных данных. Поиск с контекстом остаётся эвристикой; ограничения описывать честно.
- Не печатать содержимое `.env`, ключи, заголовки авторизации и рабочие реплики. В логах — только безопасные коды ошибок.
- Временные материалы хранить в исключённой `.work/`. Завершать только свои тестовые процессы и серверы.
- Поддерживать README, PROJECT_SPEC, ROADMAP, CHANGELOG и один план текущей существенной задачи. Проверки соразмерны изменению.
