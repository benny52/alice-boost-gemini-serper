# Правила AliceBoost

## Назначение и границы
Навык возвращает короткий русский ответ в формате Яндекс Диалогов. LLM_BACKEND выбирает Gemini/Serper (gemini, значение по умолчанию) либо GPT-OSS 120B/Cerebras через OpenRouter с предварительным Exa Instant (openrouter). Неизвестный режим возвращает ошибку настройки до обращения к внешним сервисам. Node.js 22+, без внешних пакетов. Живые обращения к API выполняются отдельно с разрешения владельца и не входят в автоматическую проверку.

## Приветствие

- При новом запуске (session.new=true) без вопроса случайно выбирается одна из трёх записей GREETINGS в lib/greeting.js. Номера звуков и подписи находятся в коде; дополнительные переменные Vercel не требуются. Собственные звуки заранее загружены в ресурсы навыка. Повтор одного варианта на следующем запуске допустим.
- В response.text возвращается подпись выбранной записи, в response.tts — тег speaker с dialogs-upload/{session.skill_id}/{id}.opus. Сессия остаётся открытой. Предупреждение о недоступной памяти добавляется и в текст, и в TTS.
- Явно пустой request.command означает отсутствие вопроса, даже если original_utterance содержит фразу активации. Только при отсутствии command используется original_utterance.
- Новый запуск сразу с вопросом обрабатывает вопрос без аудиоприветствия. Пустая реплика в уже открытой сессии не повторяет запись.
- Отсутствующий или неверный skill_id сохраняет стандартное текстовое приветствие. При переносе кода в другой навык нужны его собственные загруженные звуки.
- Приветствие не вызывает модель/поиск и не добавляется в историю. Прежнее чтение Supabase при запуске сохраняется. Доступность и фактическое воспроизведение загруженного звука проверяются в Яндекс Диалогах, локальная проверка подтверждает только корректность ответа.

## Память
- MEMORY_BACKEND=session (по умолчанию) читает state.session и возвращает session_state. Для переноса контекста Яндекс должен передавать состояние; новая сессия его очищает.
- MEMORY_BACKEND=supabase включает историю между запусками через SUPABASE_URL и серверный SUPABASE_SERVICE_ROLE_KEY. Подключение и SQL описаны в [инструкции](SUPABASE_SETUP.md). Неверная явная конфигурация останавливает обработку до внешних вызовов.
- В Supabase сохраняются последние четыре пары user/model, до 1200 символов в каждой реплике, и ограниченная тема search.query. Сохраняется конечный озвученный ответ без рассуждений и технического предупреждения о памяти. Старые обмены вытесняются; отдельного постоянного хранилища фактов нет.
- Ключ записи — SHA-256 от версии формата, skill_id, типа идентификатора и user.user_id; если пользователя нет, используется application.application_id. История разделена по навыку и пользователю/приложению. Нет skill_id или обоих идентификаторов — база не используется и сообщается о неподтверждённой записи.
- Успешно прочитанная база является источником истории даже при новой сессии или пустой записи; входящее состояние Яндекса её не заменяет. При ошибке чтения допускается ответ из доступного состояния сессии, но запись в базу запрещена, чтобы не затереть историю.
- Команды «Забудь всё», «Забудь разговор», «Начнём сначала» очищают историю и тему без вызова модели. В Supabase подтверждение очистки даётся после успешной записи; остаётся пустая запись с новой revision.
- Запись выполняется только при совпадении прочитанной revision; для отсутствующей записи используется INSERT без upsert. Это защищает сохранённую историю и очистку от запоздавших ответов. При конфликте нет повтора: новый обмен может не сохраниться, пользователь получает предупреждение. Это не очередь для одновременных разговоров.
- Ошибка модели не записывается как ответ и не меняет историю в базе. При ошибке или таймауте записи успешный ответ озвучивается с коротким предупреждением, Яндексу возвращается прежняя история. Таймаут записи не доказывает её отмену на сервере: подтверждение могло не прийти.
- Весь возвращаемый session_state, включая поисковые метаданные, по-прежнему не превышает 1024 байта UTF-8. В режиме Supabase это сокращённая копия: полные четыре пары читаются из базы. Кириллица, emoji и JSON-экранирование учитываются.
- В режиме Supabase хранилище Яндекс Диалогов необязательно; без него при сбое базы запасной истории нет. Старый формат state.session={history:[...]} поддерживается в режиме session.
- История и тема сохраняются обычным текстом в JSON; TTL не предусмотрен. Хеш скрывает исходные идентификаторы в ключе, но не является шифрованием истории. Серверный секрет обхода RLS используется только на сервере, доступ anon/authenticated отозван.
- Для памяти нет дополнительных вызовов LLM. Передача четырёх пар увеличивает входные токены и может повлиять на стоимость и задержку. Подтверждённые результаты на искусственных сервисах не являются замером Supabase.

## Поиск в режиме Gemini/Serper
- Явный запрос поиска, признаки актуальности, годы и некоторые вопросы о действующих должностных лицах запускают поиск.
- Творческие запросы без явной просьбы искать не запускают поиск лишь из-за слова «погода».
- Короткое продолжение поискового разговора использует прежнюю тему; для местоимений добавляется краткий контекст предыдущего ответа.
- В погодном продолжении заменяется относительная дата либо город. Для сложных неоднозначных фраз остаётся эвристическое поведение, без обещания полного понимания смысла.
- Читаются до трёх поисковых выдержек и краткий ответ поисковика. Полные страницы не загружаются. Источники рассматриваются как данные, а не инструкции.
- При отсутствии ключа, ошибке, пустой выдаче или таймауте Serper возвращается явное сообщение о невозможности проверки. Gemini в этой ветке не вызывается.
- Дополнительного вызова Gemini для принятия решения о поиске нет.

## Режим OpenRouter
- Ключ OPENROUTER_API_KEY используется только при LLM_BACKEND=openrouter. Gemini и Serper в этой ветке не вызываются; автоматического возврата к ним при ошибке нет.
- Модель openai/gpt-oss-120b, provider.only=[cerebras/fp16], allow_fallbacks=false, require_parameters=true. Модель и маршрут закреплены в коде; наличие ключа не переключает режим.
- Запросы идут в REST API через встроенный fetch, с готовым JSON-ответом, без потоковой передачи Алисе.
- Системная роль — «Супер Гений», русскоязычный помощник в навыке Алисы; передаётся текущее время UTC. История user/model преобразуется в user/assistant.
- GPT-OSS не поддерживает полное отключение рассуждений. Используются reasoning.effort=low и exclude=true. Общий max_tokens=1024 включает скрытые рассуждения и конечный ответ; голосовой стиль остаётся кратким.
- Решение о поиске принимают локальные правила, включая «ближайшую» или «следующую гонку». Для актуального вопроса передаётся один предварительный плагин web: engine=exa, mode=instant, max_results=3. Поисковый контекст уточнения включается в последнее сообщение. Вызовов server tools и отдельной генерации ради выбора поиска нет.
- Для обычных вопросов передаётся plugins=[] и не передаются tools. Модель не может сама инициировать поиск в этом запросе. Правила эвристические: возможны ложные срабатывания и пропуски; при пропуске можно явно сказать «найди». После смены темы поиск не сохраняется автоматически.
- Плагину задана русская инструкция без требования озвучивать источники. Выдержки источников обрабатываются как данные, а не инструкции; поиск оплачивается отдельно с баланса OpenRouter.
- При обязательном поиске, положительном счётчике поиска или наличии url_citation требуется хотя бы одна аннотация с HTTP(S)-ссылкой и непустой выдержкой. Счётчик поиска может отсутствовать; проверяются сами аннотации. При отсутствии подтверждения возвращается русская ошибка без записи ответа в историю.
- Наличие источников не гарантирует их актуальность, соответствие вопросу или правильность ответа; автоматической проверки всех фактов нет.
- Модель получает требование отвечать полностью по-русски, переводить названия или передавать их кириллицей. Оформление, ссылки и номера цитат удаляются; русские подписи ссылок сохраняются, доменные подписи не озвучиваются. Если после очистки остаются буквы вне кириллицы, ответ отклоняется с русским сообщением об ошибке. Это проверка письменности, не гарантия правильного русского языка; латинские марки, код и формулы с иностранными буквами также будут отклонены.
- Скрытые рассуждения и tool_calls не попадают в речь или память. Неполный, пустой, неподтверждённый, иностранный ответ или превышение токенов не записываются как успешный обмен.
- Ошибки доступа, баланса, квоты, языка и поиска имеют безопасные коды. Платных повторов, дополнительных переводов и запасных провайдеров нет.
- Внешний вызов получает оставшийся общий бюджет за вычетом 200 мс и резерва записи памяти, максимум 3400 мс. Он охватывает поиск, генерацию и чтение JSON; отмена соединения не гарантирует возврата расходов у провайдера.
## Время и ошибки
- Внутренний бюджет обработчика — 3600 мс, из него 200 мс резервируется на формирование ответа.
- Чтение Supabase ограничено 450 мс, запись — 350 мс. Все стадии входят в общий бюджет; при успешном чтении перед поиском/генерацией резервируется время записи. Фоновых записей и автоматических повторов нет.
- Serper получает до 1500 мс. Доступное время поиска дополнительно ограничивается остатком общего бюджета с резервом 1800 мс для Gemini, 200 мс для ответа и, при необходимости, 350 мс для записи истории.
- Gemini получает остаток общего бюджета за вычетом резервов ответа и записи истории, максимум 3400 мс. Время уже выполненного поиска вычитается; независимые максимумы поиска и генерации не складываются.
- Таймаут отменяет HTTP-запрос и чтение JSON-тела. Стандартные AbortError/TimeoutError нормализуются в код таймаута.
- Соединение Яндекса с Vercel, холодный запуск и доставка ответа не измеряются локальным бюджетом. Лимит платформы — 4,5 секунды; гарантия полного ответа при любых условиях не даётся.
- Отложенной генерации, повторов API и сценария «дальше» нет. Долгий запрос отменяется с понятной репликой.
- Ответ ограничен 1024 символами JavaScript-строки, генерация Gemini — 240 выходными токенами; лимит OpenRouter описан отдельно выше. Используется краткий голосовой стиль.
- Ошибки обработчика записываются безопасными кодами. Для внешних запросов событие `UPSTREAM_REQUEST` содержит только `service` (gemini/serper/openrouter/supabase/external), `elapsed_ms`, `timeout_ms`, `http_status` (либо null, если статус не получен) и `outcome` (ok/http_error/timeout/network_error/response_error). URL, заголовки, тело запроса/ответа и текст исключения не записываются.

## Проверка и размещение
Автоматические тесты проверяют реальный обработчик, заменяя только внешние сервисы. Локальный запуск слушает 127.0.0.1, принимает `/api` и ограничивает размер JSON-запроса 32 КиБ.

Перед размещением нужны отдельные решения о защите вебхука, лимитах расходов и доступе; живые испытания модели, поиска и колонки. Нельзя считать эти пункты выполненными по результатам локальных тестов.
