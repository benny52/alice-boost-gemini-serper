# Постоянная история разговора — план

Статус: завершён, опубликован и проверен через Vercel. Владелец выбрал первый этап: история разговора, без отдельной памяти фактов.

## Результат и подход

Supabase хранит последние четыре пары реплик и тему поиска между запусками.
Разделение по skill_id и user.user_id; при отсутствии пользователя — по
application.application_id. В базе используется хеш идентификаторов.
Нет идентификатора — нет общей записи для анонимных пользователей.
Новая сессия восстанавливает историю из базы. В режиме Supabase база является
источником истории, входящее состояние Яндекса не заменяет её.

MEMORY_BACKEND=session по умолчанию сохраняет прежнее поведение.
MEMORY_BACKEND=supabase включает SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY
(серверный sb_secret_ либо совместимый старый service-role JWT).
Подключение через встроенный fetch/PostgREST, без новых пакетов.

Чтение до 450 мс, запись до 350 мс, общий срок обработчика 3600 мс сохраняется.
Перед генерацией резервируется время записи. При сбое чтения используется
доступное состояние сессии, но запись в базу запрещена. Успешный ответ может
быть озвучен с сообщением о неподтверждённом сохранении. Ошибка модели историю
не меняет. Подтверждение сохранения или очистки — только после успешной записи.

Запись по ожидаемой revision защищает от затирания параллельного изменения.
При конфликте без повторов возвращается предупреждение; новый обмен может
не сохраниться, уже записанная история остаётся. Очистка оставляет пустую
запись с увеличенной revision, чтобы старый запрос не восстановил удалённые
реплики. Это не очередь диалогов и не гарантия сохранения всех одновременных
обменов.

История в базе — до восьми сообщений по 1200 символов; возвращаемый Яндексу
session_state остаётся не больше 1024 байт. Это контекст последних обменов,
старые факты вытесняются. Дополнительных вызовов LLM для памяти нет.

Существующая feature/aliceboost, без push, main и деплоя. Изначальный локальный этап не включал живые API; позднее владелец отдельно разрешил локальную проверку настоящей базы и разговора.
Владелец добавил ключи Supabase в .env и сообщил о выполнении SQL. SQL предоставляется для отдельного применения
владельцем; не запускать его в рабочей базе без команды. Локального PostgreSQL
не обнаружено: отличать HTTP-моделирование от проверки реальной базы.
Принять SQL как реально проверенный можно только после отдельного исполнения.
