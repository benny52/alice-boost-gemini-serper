# Подключение истории Supabase

Код подготовлен для локальной проверки. Применение SQL, проверка рабочей базы,
платные обращения к модели и публикация выполняются отдельно. Поведение и
ограничения истории описаны в [спецификации](PROJECT_SPEC.md#память).

## 1. Создать проект

Создайте проект на [Supabase Free](https://supabase.com/dashboard).
Для текущей функции Vercel в Washington (`iad1`) выберите
**East US — North Virginia (`us-east-1`)**. Дождитесь готовности проекта.

На Free проект может приостанавливаться после недели бездействия. Такое состояние
не укладывается в срок голосового ответа: потребуется восстановить проект.
[Регионы](https://supabase.com/docs/guides/platform/regions),
[условия Free](https://supabase.com/pricing).

## 2. Создать таблицу

В SQL Editor откройте новый запрос, вставьте целиком
[supabase/memory.sql](../supabase/memory.sql) и выполните Run.

Скрипт совместим с ранее предложенной таблицей с полями conversation_id, history
и updated_at: добавляет search и revision, не удаляя записи. Не удаляйте пустые
записи после команды очистки: их revision защищает от запоздавших запросов.
Старые записи с другим способом формирования conversation_id автоматически
не переносятся.

Таблица недоступна ролям anon и authenticated; RLS включён. Только сервер
использует service_role. Применять SQL должен владелец проекта. Результат живой проверки см. в [отчёте](reports/2026-10-16-supabase-check.md).

## 3. Сохранить параметры локально

Скопируйте Project URL из Connect, а серверный Secret key (`sb_secret_…`) из
Settings → API Keys. Добавьте в существующий `.env`, сохранив остальные строки:

```dotenv
MEMORY_BACKEND=supabase
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVER_SECRET
```

Имена параметров буквальные. Значения с YOUR замените настоящими.
Название SUPABASE_SERVICE_ROLE_KEY сохранено для совместимости: в него подходит
новый `sb_secret_…`, а также старый service-role JWT. Публичный anon/publishable
ключ не подходит. Ключ не отправляйте в чат, не публикуйте в GitHub и не включайте
в URL вебхука.

[О ключах Supabase](https://supabase.com/docs/guides/getting-started/api-keys).

Без MEMORY_BACKEND либо при значении session база не используется.
Простое добавление ключей не включает историю. Неверная настройка включённой
памяти возвращает сообщение до обращения к модели.

## 4. Проверить локально

Автоматические тесты `npm test` работают с искусственными данными, не читают
`.env` и не обращаются к настоящим Supabase/OpenRouter.

После отдельного согласования живой проверки запустите `npm start` и отправьте
запросы в `/api` с одинаковыми session.skill_id и session.user.user_id:

1. «Моего кота зовут Барсик».
2. Новый запрос с session.new=true, без state.session: «Как зовут моего кота?».
3. «Забудь всё», затем снова спросите имя кота.
4. Проверьте другой user_id: чужое имя не должно восстанавливаться.

Генерации в этой проверке платные. Проверка GET `/api` не проверяет базу.

## 5. Включить на Vercel после разрешения публикации

В Production задайте:

| Переменная | Тип | Значение |
| --- | --- | --- |
| MEMORY_BACKEND | Config | supabase |
| SUPABASE_URL | Config | Project URL |
| SUPABASE_SERVICE_ROLE_KEY | Secret | Серверный ключ |

Прежние LLM_BACKEND и OPENROUTER_API_KEY сохраняются. После публикации нового
кода и переменных нужен Redeploy. Локальный `.env` в Vercel не переносится.

В режиме Supabase галочку «Использовать хранилище данных в навыке» Яндекс Диалогов
можно оставить выключенной: история читается по пользователю и навыку.
После размещения проверьте на том же аккаунте: сообщите имя кота, выйдите из
навыка, войдите снова и спросите имя. Затем проверьте «Забудь всё».
В логах будут отдельные UPSTREAM_REQUEST с service=supabase — только время,
статус и исход, без ключей, идентификаторов и реплик.
