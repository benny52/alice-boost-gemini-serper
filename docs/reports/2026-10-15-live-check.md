# Живая локальная проверка — 15 октября 2026

Проверялся коммит `faf4813`, модель `gemini-3.5-flash-lite`. Реальные Gemini и Serper вызывались с явного разрешения владельца. Публикации и изменения рабочего кода не выполнялись.

## Условия

- Windows, Node.js 22.22.3; настоящий локальный HTTP-сервер на 127.0.0.1 и случайном порту.
- Ключи загружались из исключённого из Git `.env`, без вывода значений. Использовались только искусственные реплики и публичные сведения.
- Без явного подключения Node к системному прокси Google отвечал HTTP 400 / FAILED_PRECONDITION с причиной неподдерживаемого региона.
- Существующий локальный прокси Windows подключался только к проверочному процессу через HTTP_PROXY/HTTPS_PROXY, NO_PROXY для loopback и `--use-env-proxy`. Настройки Windows, `.env` и команды проекта не изменялись.
- Во время первых серий владелец переключал VPN. Эти результаты нельзя объединять с последней серией в одну статистику стабильного подключения.
- На последнем подключении Google успешно ответил; выбранная модель была ранее подтверждена через список моделей API.

## Последние замеры после переключения VPN

Время включает запрос к локальному обработчику и чтение его ответа. Это отдельные наблюдения, не p95 и не гарантия скорости.

**Диагностика** использовала временную копию обработчика с теми же правилами памяти и поиска, но лимитами Serper 8 с, Gemini 12 с и общим бюджетом 25 с. В основной код эти лимиты не переносились. Успех диагностики подтверждает функциональность, но не прохождение штатного таймаута и не пригодность для ответа Алисе за 4,5 с.

В ранней серии со штатными таймаутами успешным был 1 из 11 запросов к внешним сервисам, остальные 10 завершились таймаутом. После окончательного переключения проверены отдельно два штатных сценария из таблицы; прежнюю долю отказов нельзя считать характеристикой последнего подключения.

## Память

- Первый успешный диалог сохранил искусственное имя «Кедр» в session_state. При таймаутах и региональном отказе API сохранённое состояние не потерялось.
- После восстановления подключения Gemini получил реальную прежнюю пару user/model и правильно вспомнил имя.
- «Забудь разговор» и новая сессия очищали заполненную память без обращения к API, за 2–5 мс.
- Во всех сохранённых ответах проверенных серий состояние не превышало 1024 байта; наибольшее наблюдение — 742 байта. Это проверка наблюдавшихся состояний, не новая исчерпывающая проверка упаковки.
- Передача состояния Яндексом здесь имитировалась клиентом: JSON session_state из ответа переносился без изменений в state.session следующего запроса. Сам Яндекс и колонка не участвовали.

## Контекст и качество поиска

Подтверждены сохранение темы фильма в местоименном уточнении и замена города с сохранением «завтра». Поисковый запрос и история действительно отправлялись внешним сервисам.

Есть ограничение качества: в раннем успешном запросе о дате выхода «Дюны: Часть вторая» модель ответила «25 февраля 2024». Повторное чтение Serper показало среди трёх выдержек список премьер Кинопоиска с этой датой для США и устаревшую статью о переносах. Для обычного театрального релиза США официальный [трейлер Warner Bros.](https://www.youtube.com/watch?v=U2Qp5pL3ovA) указывает 1 марта 2024 года. Навык не различил ранний показ/премьеру и широкий прокат. В последнем повторе модель уже отказалась назвать точную дату.

Следовательно, найденные выдержки не гарантируют точного ответа. Текущий запрос также сохраняет разговорные инструкции вроде «Ответь одной датой» и может включать прежний неинформативный ответ. Очистка поисковых запросов, различение видов дат и проверка противоречий — направления для обсуждения, не выполненные изменения.

## Хранилище Яндекса

Владелец передал совет автора временно отключить хранилище из-за сбоя. Официальное подтверждение именно этого инцидента при проверке не найдено; это не доказывает отсутствие сбоя.

По действующей [документации](https://yandex.ru/dev/dialogs/alice/doc/ru/session-persistence) для возврата session_state нужно включить «Использовать хранилище данных в навыке». У AliceBoost нет отдельного хранилища: отключение уберёт память и контекст между репликами. Локальные задержки Gemini/Serper не связаны с этой настройкой.

## Вывод и следующий шаг

1. Память и проверенные поисковые продолжения работают с реальными сервисами, когда те успевают ответить.
2. Штатный лимит Serper 600 мс меньше всех успешных локальных наблюдений поиска. Таймауты корректно ограничивают ожидание, но часто не дают полезного ответа.
3. Локальная сеть и VPN существенно влияют на результат. На Vercel маршрут к API будет другим и может оказаться быстрее; из локальных замеров нельзя вывести облачную задержку.
4. У Яндекса [4,5 секунды на весь путь](https://yandex.ru/dev/dialogs/alice/doc/ru/wait-response), включая сеть. Просто перенести длинные диагностические таймауты в приложение нельзя.
5. До изменения архитектуры разумно отдельно согласовать размещение для проверки и измерить исходящие запросы именно из выбранной среды Vercel. После этого выбирать перераспределение бюджета, модель или иной сценарий ответа. Защита вебхука и расходы требуют решения перед публичным доступом.

Все проверочные серверы завершены. Ключи, адрес прокси и частные данные в отчёт не включены. GitHub и Vercel не изменялись.
