# AliceBoost

Навык Яндекс Алисы с короткой памятью разговора. Доступны два явных режима: Gemini + Serper или GPT-OSS 120B через Cerebras/OpenRouter + предварительный поиск Exa Instant.

Основа: [alice-gemini-serper-template](https://github.com/ruslanpodzorovraw-collab/alice-gemini-serper-template), исходный коммит `3fb62838a1fcb2efcf1135d3b82319beabee4114`. Сохранены история Git и лицензия MIT. Рабочая ветка — `feature/aliceboost`.

## Локальная настройка

Нужен Node.js 22 или новее. Внешних пакетов нет, устанавливать зависимости не требуется.

1. Если файла `.env` ещё нет, скопируйте `.env.example` в `.env`. Существующий `.env` не перезаписывайте.
2. Выберите режим в `.env`: `LLM_BACKEND=openrouter` и `OPENROUTER_API_KEY` для нового варианта; либо `LLM_BACKEND=gemini`, ключ Gemini из [Google AI Studio](https://aistudio.google.com/app/apikey) и `SERPER_API_KEY` из [Serper](https://serper.dev/) для прежнего. Без `LLM_BACKEND` сохраняется Gemini; наличие ключа OpenRouter само по себе режим не переключает.
3. В OpenRouter закреплены `openai/gpt-oss-120b` и только `cerebras/fp16`, без запасных провайдеров. Отдельный ключ Exa не нужен: поиск оплачивается с баланса OpenRouter. Для прежнего режима модель задаётся через `GEMINI_MODEL`.
4. Выполните `npm start`. Сервер будет слушать только локальный компьютер: `http://127.0.0.1:3000/api`.
5. Для остановки нажмите Ctrl+C.

`.env` исключён из Git. Не отправляйте ключи в сообщения и не помещайте их в исходники. Ключ Vercel для локального запуска не нужен.

Открытие `/api` в браузере проверяет только работу обработчика, а не доступность выбранной модели или поиска. Для диалога нужно отправлять POST в формате Яндекс Диалогов и, в режиме памяти session, переносить `session_state` ответа в `state.session` следующего запроса.

## Случайное аудиоприветствие

При новом запуске без вопроса воспроизводится одна из трёх записей: «Импортирую установки, начинаю калибровку виртуальной среды», «Мы подключены и готовы» или «Всегда к вашим услугам, сэр». Их номера и подписи закреплены в [lib/greeting.js](lib/greeting.js). Дополнительных переменных Vercel не требуется. Запуск сразу с вопросом пропускает приветствие.

Записи заранее загружены в ресурсы текущего навыка. При переносе в другой навык загрузите свои файлы в Яндекс Диалоги → Ресурсы → Звуки и замените их номера в GREETINGS. Идентификатор навыка берётся из session.skill_id. Номера звуков не являются ключами API. [Правила запуска](docs/PROJECT_SPEC.md#приветствие), [формат собственных звуков Яндекса](https://yandex.ru/dev/dialogs/alice/doc/ru/resource-sounds-upload).

## История между запусками

По умолчанию используется состояние Яндекса. Для сохранения последних четырёх обменов между запусками подготовлен режим Supabase: [пошаговое подключение и SQL](docs/SUPABASE_SETUP.md). Режим опубликован на Vercel в коммите 38459e9. [Сквозная проверка](docs/reports/2026-10-16-supabase-check.md) подтвердила запоминание, восстановление в новой сессии и очистку с настоящими моделью и базой; ограничения одного прогона и проблемы локального клиента описаны в отчёте. Дополнительных вызовов модели для памяти нет, но история увеличивает входные токены.

## Автоматическая проверка

```text
npm test
```

Тесты не загружают `.env`, используют искусственные ключи и контролируемые ответы вместо сетевых запросов. Проверяются память, выбор и контекст поиска, ошибки и отмена запросов. Наличие зелёных тестов не означает, что измерена реальная скорость внешних сервисов.

## Живые проверки

15 октября 2026 выполнены проверки с реальными сервисами. Условия, замеры и ограничения зафиксированы отдельно в [локальном отчёте](docs/reports/2026-10-15-live-check.md) и [отчёте Vercel](docs/reports/2026-10-15-vercel-check.md). После публикации новых лимитов выполнена [повторная проверка Vercel 16 октября](docs/reports/2026-10-16-vercel-timeout-check.md): поиск проходит, но ошибки и таймауты Gemini ещё мешают стабильным ответам. Проверка на колонке пока не выполнялась.

[Предыдущая проба DeepSeek через OpenRouter 16 октября](docs/reports/2026-10-16-openrouter-check.md): DeepInfra + Exa дали ответ с источниками за 4964 мс через системный HTTP-клиент, стоимость $0,00714082. Ускорение для Алисы не подтверждено. Из локального Node.js получен HTTP 403, причина различия клиентов ещё не установлена. На Vercel новая ветка не проверялась и не публиковалась.

[Проба GPT-OSS 120B/Cerebras 16 октября](docs/reports/2026-10-16-cerebras-check.md): предварительный Exa Instant и полный ответ заняли 1824 мс, стоимость $0,00765165. Это один запрос через системный HTTP-клиент до изменения обработчика. Интеграция прошла локальные проверки и опубликована. Владелец подтвердил успешный ответ на вопрос о Формуле-1: поиск Exa Instant и полный ответ модели через OpenRouter заняли на стороне Vercel 1198 мс. Это один серверный замер, без всей задержки Алисы; качество ответа и границы измерения разобраны в отчёте.

## Поведение и ограничения

Согласованные правила и ограничения описаны в [спецификации](docs/PROJECT_SPEC.md). Главные отличия от шаблона:

- Состояние сессии укладывается в 1024 байта UTF-8; старые сообщения удаляются, слишком длинные последние сообщения сокращаются.
- Поиск понимает некоторые продолжения вопросов и даты. Например, после погоды в Москве можно уточнить «А завтра?» или «А в Санкт-Петербурге?».
- Если поиск не удался, не подключён или не нашёл сведений, навык сообщает об этом. Свежие факты не подменяются ответом без проверки.
- Таймаут охватывает и соединение, и чтение тела ответа. Поиск и генерация делят общий бюджет: Gemini использует время, оставшееся после поиска. При отмене сохраняется ограниченный контекст.
- В OpenRouter ответ полностью на русском: названия переводятся или передаются кириллицей. Если модель оставила иностранные буквы, возвращается русское сообщение об ошибке без повторного расхода; старый контекст сохраняется.
- Команды «Забудь всё» и «Забудь разговор» очищают контекст. В режиме Supabase история переживает завершение сессии; при недоступности базы навык сообщает о неподтверждённом сохранении.

В обоих режимах решение о поиске принимают локальные правила. В OpenRouter актуальные вопросы получают предварительный поиск Exa Instant; обычные запросы идут без поискового плагина. Модель сама не запускает дополнительный поиск. Возможны лишние или пропущенные поиски; наличие источника само по себе не гарантирует правильность ответа. Сложные продолжения лучше формулировать полностью. Объём истории и поведение двух режимов памяти описаны в спецификации.

## Тестовое размещение

Владелец создал тестовое размещение из main на Vercel. Проверки используют Vercel Authentication и секрет для автоматизированного доступа. Сам обработчик не содержит собственной авторизации; доступ Яндекса и ограничения расходов требуют отдельного решения. Локальный сервер слушает только 127.0.0.1.

Vercel использует обработчик `api/index.js` и конфигурацию функции. Выбранный LLM_BACKEND и соответствующие ключи задаются в окружении размещения; локальный .env туда автоматически не переносится. Для переключения размещения сначала требуется отдельное разрешение владельца. HTTPS-адрес `/api` используется как вебхук Яндекс Диалогов; локальный адрес для колонки не подходит. Хранилище Яндекса нужно для памяти в режиме session; в режиме Supabase оно необязательно. Поведение при сбоях описано в спецификации.
